# CPR / CPRM

사용자 공용 Git 작업 스킬이다. 현재 작업 저장소의 지침·검증 명령·브랜치 정책을 읽어 적용한다.

- `cpr`: 현재 합의된 변경의 commit → push → PR 생성/업데이트.
- `cprm`: 위 작업 → 요청 대상 브랜치로 PR 병합 → 가능한 경우 깨끗한 로컬 대상 브랜치 동기화.
- 단순 설명이나 스킬 수정은 위 동작의 실행 승인이 아니다. 외부 배포와 별도 저장소의 변경은 포함하지 않는다.

## 실행

1. 현재 저장소·브랜치·remote·전체 변경을 확인하고 AGENTS.md 등 저장소 지침을 읽는다. 프로젝트 전용 PR 게이트 스킬이 있으면 함께 읽는다. 특정 프로젝트 경로나 npm 명령을 다른 저장소에 가져가지 않는다.
2. 요청된 변경만 포함한다. 기존 작업 브랜치를 사용하고 대상 기본 브랜치에서는 저장소 정책에 맞는 작업 브랜치를 만든다. 무관한 변경을 보존하고 파일을 명시적으로 stage한다.
3. 저장소가 요구하는 타입 검사·빌드·검증·CI 게이트를 실행한다. 기존 도구와 설치된 의존성을 사용한다. 실패는 해결하고 게이트를 우회하지 않는다.
4. 인수 조건은 Markdown을 재사용한다. 필요한 경우에만 현재 목표의 임시 실행 스크립트를 만들고, 실제 통과 후 소스 상태·명령·환경·결과·미검증 범위를 기록하고 스크립트를 폐기한다. 원본 관측·재사용 입력은 보존한다. 실행 스크립트가 없으면 이번 실행을 생략하고 과거 통과와 현재 미검증을 구분해 기록한다. 이는 다른 필수 게이트를 생략하는 권한이 아니다.
5. 커밋 직전 staged diff와 status를 확인해 비밀·임시 로그·무관한 파일이 섞이지 않게 한다. 저장소의 커밋 규칙을 따르고 실제 작업자와 무관한 작성자 표기를 추가하지 않는다.
6. 작업 브랜치를 해당 remote에 push하고 훅이 끝날 때까지 확인한다. force push와 이력 재작성은 별도 사용자 요청 없이 수행하지 않는다.
7. 같은 브랜치의 PR이 있으면 업데이트하고 없으면 저장소가 정한 대상 브랜치로 생성한다. 이유·변경·실제 검증·미검증을 기록한다. 여러 줄 본문은 임시 파일과 CLI의 body-file 옵션 또는 구조화된 API로 전달한다. PR 연결 도구가 있으면 현재 작업에 연결한다.
8. `cpr`이면 PR 상태를 확인하고 종료한다. `cprm`이면 최신 head SHA·필수 검사·충돌·승인 조건을 확인하고 저장소의 병합 방식으로 병합한다. 보호 규칙을 우회하지 않는다. 검증한 head가 바뀌면 새 변경을 확인한다.
9. 병합 후 PR의 실제 merged 상태와 커밋을 확인한다. 로컬 대상 브랜치가 깨끗하고 다른 작업이 사용하지 않으면 fast-forward로 동기화한다. 사용자 변경을 덮어쓰거나 다른 worktree를 정리하지 않는다.

## 운영과 결과

- Storybook 업데이트·배포는 사용자의 명시적 요청으로 별도 수행한다. 배포 기록 불일치를 이유로 CPR 중 배포를 준비하거나 승인 요청을 만들지 않는다.
- 커밋할 변경이 없으면 push 여부와 기존 PR을 확인한다. 빈 커밋·중복 PR을 만들지 않는다.
- 실제 커밋 SHA·브랜치·PR 링크·검증 결과를 보고한다. `cprm`에서는 병합 커밋·로컬 동기화 여부도 확인한다. 실패·미실행을 성공으로 바꾸지 않는다.
