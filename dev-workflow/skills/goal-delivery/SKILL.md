# Goal Delivery

사용자가 승인한 목표 하나를 구현·검증·보고할 수 있는 단위로 정리한다. 현재 프로젝트의 문서와 기존 인수 기준을 재사용하고 중복 계획·날짜별 문서를 만들지 않는다.

## 1. 도메인 → 목표와 범위

- 현재 작업 저장소의 지침, 제품·구조·설계 문서, 현재 목표의 인수 Markdown을 직접 읽는다. 문서 이름·위치·테스트 언어는 프로젝트에서 찾는다. 기존 파일이 없으면 필요한 인수 Markdown 하나만 적절한 위치에 만든다.
- 사용자에게 제공할 결과·실패 조건·완료 기준·비목표를 고정한다. 누락된 정보를 새 제품 요구로 추정하지 않는다.
- 지켜야 할 데이터·권한·동작 불변식을 정의한다. 실제 관측과 추정, 저장 성공과 사용자에게 사용 가능함을 구별한다.
- 기존 사용자 데이터·프로필·세션·자격증명·무관한 변경을 보존한다. 외부 전송·배포·Git 작업은 사용자가 요청한 범위와 현재 환경의 권한을 따른다.

## 2. 목표 → Markdown 인수 기준

기존 인수 ID를 이어 쓰고 제품의 공개 진입점에서 입력 → 실제 처리 → 결과·저장 상태를 확인한다.

```text
A<n>  <사용자 시나리오>
Given  <초기 상태·입력>
When   <사용자 행동>
Then   <관측할 제품 결과·보존할 상태·실패 조건>
```

- 내부 함수 호출·mock 성공만 확인하는 사례를 인수 테스트로 이름만 바꾸지 않는다. 비목표를 인수 ID로 만들지 않는다.
- 인수 조건의 원천은 재사용할 Markdown이다. 입력·기대 결과·검증 방법·환경 제약을 함께 적는다.
- 자동 실행이 필요한 경우에만 해당 문서에서 현재 목표의 임시 스크립트를 만든다. 프로젝트가 사용하는 언어·실행 도구를 따른다. 별도 단위·회귀 테스트 계층을 추가하지 않는다.

## 3. 인수 ID → 담당 작업과 의존성

- 필요한 변경을 기존 코드의 연결 위치에서 도출하고 작업마다 파일·쓰기 범위·선행 검증을 명시한다.
- 공유 파일의 병렬 쓰기를 피한다. 담당자는 충돌·범위 확장·권한 부족을 조정 담당에게 보고한다.
- 삭제·기존 유틸리티·기존 패턴을 우선한다. 임의의 의존성·새 러너를 추가하지 않는다.

## 4. 구현 → 실제 검증과 정리

- 각 인수 ID를 증명하는 최소 검증을 수행한다. 자동 인수·타입 검사·빌드·실제 앱·실제 모델·사람 검수를 구별한다.
- 실제 통과 후 인수 Markdown에 검증한 소스 상태·명령·환경·결과·미검증 범위를 남기고 해당 임시 스크립트를 폐기한다. 원본 관측과 재사용 입력은 보존한다.
- 실패·결과 불명인 스크립트를 폐기해 성공으로 처리하지 않는다. 재검증이 필요하면 보존한 문서에서 다시 구현한다.
- 실행 스크립트가 없으면 이번 실행을 생략하고 현재 미검증을 기록한다. 과거 통과를 변경 후 소스의 새 통과로 해석하지 않는다. 저장소의 다른 필수 게이트는 유지한다.
- UI smoke·앱 캡처·Storybook·실제 모델 실행은 사용자의 명시적 요청과 데이터 접근 권한에 따라 수행한다.
- 검증 로그는 현재 저장소의 Git 제외 위치 또는 임시 디렉터리에만 둔다. 완료 기록은 기존 인수 문서·Git/PR에 요약한다.

## 5. 결과 보고

변경한 범위·이유, 인수 ID별 실제 결과, 미검증·남은 차단 조건을 보고한다. 게이트 통과·모델 문장·테스트 개수를 목표 인수 완료로 승격하지 않는다.

## 연결

- 조정 에이전트가 Claude 이외이고 사용자가 Claude 모델·effort·역할·세션 구성을 명시해 실행을 요청하면 [claude-sessions](../claude-sessions/SKILL.md)를 사용한다. Claude 자신과 위임받은 Claude 세션은 이 연결을 사용하지 않는다.
- 조정 에이전트가 Codex 이외이고 사용자가 Codex 모델·effort·역할·세션 구성을 명시해 실행을 요청하면 [codex-sessions](../codex-sessions/SKILL.md)를 사용한다. Codex 자신과 위임받은 Codex 세션은 이 연결을 사용하지 않는다.
- 사용자가 CPR/CPRM을 요청하면 [cpr](../cpr/SKILL.md)를 따른다. 목표 구현 요청만으로 Git 작업·배포를 실행하지 않는다.
- 인수 표가 필요한 경우에만 [references/delivery-scaffold.md](references/delivery-scaffold.md)를 읽는다.
