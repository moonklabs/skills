# Goal delivery scaffold

현재 프로젝트의 기존 목표·인수 Markdown을 먼저 찾고 해당 파일에 필요한 부분만 반영한다.

```text
목표: <사용자에게 제공할 결과>
비목표: <이번에 포함하지 않는 범위>
도메인 불변식: <지켜야 할 동작·데이터 조건>
원천: <실제로 읽은 저장소 지침·제품·설계·인수 문서의 경로>
```

| ID | 시나리오 | Given | When | Then | 담당·의존성 | 검증 방법 | 결과·미검증 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A1 | | | | | | | |

- 검증은 자동 인수 / 타입 검사·빌드 / 실제 앱 / 실제 모델 / 사람 검수로 구분한다.
- 실제 통과 후 소스 상태·명령·환경·관측 결과·미검증 범위를 남기고 임시 실행 스크립트를 폐기한다. 인수 Markdown과 재사용 입력은 보존한다.
- 스크립트가 없으면 이번 실행을 생략한다. 과거 검증과 현재 미검증을 구분한다. 재검증은 이 문서에서 다시 구현한다.
